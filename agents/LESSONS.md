
## Morning Coffee collection

- Collect personal review history before request targets; only an effective personal approval needs current-target and re-request timeline evidence. Keep unknown evidence visible.
- Preserve raw provider responses outside the repository and return a single compact projection with pagination/completeness markers. Quoted search aliases still need local match validation.
- A source connected in one local host is not necessarily available to the host running collection. Verify the collector's own tool catalog, register the same approved endpoint there when authorized, and confirm a real read from a fresh context before collecting; configured, enabled or listed alone proves nothing.
- Keep display policy such as local daytime hours in the installed renderer and skill instructions. A private publication wrapper fixes one report and hides the gap from the next run.
- Keep authored open PRs separate from review-request queues: they include drafts, use different sorting and controls, retain independent coverage, and preserve their selected tab through live refreshes.

## Local daily planner state

- New optional blocks start unplaced; confirmed choices are separate from fixed calendar evidence and populate Today only after persistence succeeds.
- Dragging previews a candidate and commits on valid drop; cancelled or invalid drops preserve the prior plan.
- Use explicit HH:MM controls for 24-hour UI; native time inputs can follow the operating system’s 12-hour locale.
- Local review completion is personal state, separate from provider approval, and must survive report refreshes without changing source eligibility.

## Local interaction delivery

- A long-running agent command is temporary. Detach local save services, confirm readiness, and verify saves after the launcher exits.
- Serve a private live report URL that reloads local state; reopening a static session HTML otherwise restores stale embedded marks.
- Browser checks must exercise the delivered page and persistence across reloads, alongside mocked control tests.
- Accept interactive delivery only after a real authenticated save and persisted reload; a successful report GET proves rendering alone. Refresh only affected sections so unrelated task, project-tag and subtask drafts, filters, focus and scroll survive updates.
- Scheduled daily work must explicitly authorize rollover, resolve the date at execution time, and complete the exact durable request. Reopening yesterday's workspace is not starting today.
- Persist private workspace connection metadata so fresh scheduled sessions reuse the same browser URL; verify both the report date and browser title after rollover.
- For dense task rows, keep frequent actions in a stable compact rail and put secondary actions in an accessible menu. Verify long titles, nested rows and narrow widths in the browser.

- An accepted suggestion must reveal the saved task and confirm success, including under active filters or a concurrent view refresh. Do not silently discard an enabled action during a background read.
- When clipboard shortcuts fail only inside an embedded browser, trace physical keyboard events separately from automation. Honor the user’s default-browser preference for both manual and scheduled reports.

- Pause local workspace polling while its tab is hidden and check immediately on return; test visibility changes during an in-flight request as well as idle timers.
- Resume workspace polling on pageshow after a back/forward-cache restore; pagehide does not always mean the document is permanently discarded.
- A local Morning Coffee dashboard can queue its existing T3 collector through scoped loopback access; a missing public webhook does not require enabling remote access.
- Explicit local calendar completion overrides elapsed-time styling, while every source interval remains reserved for scheduling.
- Time-based Coffee/Tea presentation includes masthead branding and coverage accents; keep it independent of legacy report modes and their layout or save permissions.

- Keep local action history separate from current state projections: restoring cleared work must not erase the clear event, and a chosen plan or elapsed block must not be reported as completed work.

- Keep chosen priorities and previous-day outcomes in one briefing above local tasks. Preserve disclosure state by stable item identity through refreshes; repeated summary labels are not identities. Measure mobile overflow against the requested viewport width, because browser auto-zoom can hide an overflowing masthead.

- Task drag moves must preserve complete subtrees and validate the full order/parent structure, including hidden filtered tasks. Once the user chooses a manual order, importance stars must not override it. Offer equivalent keyboard movement and keep the confirmed tree until a matching save succeeds.
