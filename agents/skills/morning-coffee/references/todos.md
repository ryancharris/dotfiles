# Local to-do list

The Morning Coffee workspace loads `load_todos(report_root, with_warnings=True)` into the session snapshot before rendering. Keep active tasks in `snapshot.todos` and the returned `todo_archive` in `snapshot.todo_archive`; all open tasks are user-entered work to account for alongside source priorities. `todo_summary(snapshot)` groups tasks by `pending` (displayed as Open), `completed` and `cancelled`, independently of the report date. Open tasks stay in the queue across days until explicitly completed or cancelled. Completed and cancelled tasks remain discoverable but are excluded from outstanding work. Source activity never implies local task completion.

The live widget saves explicit add, complete, cancel, reopen, clear, restore and undo actions through the authenticated loopback `/todo` endpoint. Any task can have subtasks, with independent statuses. Open, Completed, Cancelled and All tasks tabs preserve ancestor context for matching subtasks. Archived lists cleared tasks separately from active work. Completing or cancelling a parent changes only that task. Clear moves a task into the durable archive and promotes its children to its parent, preserving their work. Clear tab asks for confirmation, then archives only the selected status matches, excluding ancestor context. Undo last clear restores the whole most recent remaining batch; each archived task also has Restore. Undo remains available after reload. Restore preserves status and importance, restores parent relationships when available, and keeps subsequent edits to surviving tasks. If a restored task’s parent is still archived, it temporarily becomes a root; restoring its parent reattaches the unchanged child. Changes appear after a matching successful acknowledgement. Archived reports show the saved state with disabled write controls.

Store active tasks and archive batches atomically in `<report_root>/todos/state.json`, across dates and report types. Cleared tasks leave active state but remain in the local archive with their clear timestamp and batch identity. Legacy stores without an archive load normally; previously deleted records cannot be reconstructed. Each task has a locally generated ID, optional `parent_id`, title, status, importance, and creation/update timestamps. Tasks have no due dates or rescheduling controls. Existing legacy `due_date` fields remain stored without affecting visibility, ordering or counts; an older report's add payload may include an ignored `due_date`. Add accepts an optional existing parent ID; flat stores load with null parents. Invalid parent links and cycles are disclosed. The lock serializes actions from concurrent workspace tabs and legacy sessions; atomic replacement preserves the prior file if a write fails. Files are private to the user. An unreadable store is disclosed and preserved rather than overwritten. Reopening a live report reloads the current store.

Publish archives without `todo_interaction`, which contains a short-lived local saving capability. Load the latest store for each new live session instead of trusting an archived task list. Task changes affect local planning only.

Completed tasks show a check emoji, struck-through title and gray text. Style only the completed item’s own entry so pending subtasks remain visually active.

Keep star, Complete/Reopen and Cancel directly visible in a compact action rail. Put Add subtask, Project tags and Clear task in the More actions disclosure; support one open menu, outside-click dismissal and Escape returning focus to its summary. Keep the rail aligned across statuses and nested rows without individual buttons wrapping. Add subtask opens a labelled input beneath that parent, before its children, while the top form continues adding root tasks. Successful child saves keep the inline input ready for another child; failed saves preserve its draft. Cancel adding or Escape closes the input without writing and returns focus to the parent’s More actions summary. Preserve unsaved child drafts across tab changes and unrelated task updates.

Use the star toggle to mark a task high importance. Stars persist across workspace refreshes, days and status changes; starred tasks sort first within the selected view. Preserve nesting: a starred descendant brings its ancestor group forward without automatically starring its parents. Older tasks default to unstarred. Apply changes only after the local store confirms the requested importance.

Project tags are optional personal labels, shared across workspace refreshes and days. Both the new-task field and More actions → Project tags editor offer a dropdown of tags from active and archived tasks, plus Create new tag. Choosing a tag updates only the draft; creating a tag accepts one name, and Add task or Save tags also includes a nonempty unfinished new-tag field. Persist tags with the task, without a separate orphan tag store. Keep tag selections and unfinished new-tag drafts across unrelated task actions and source refreshes. Show selected tags as removable draft chips beside one dropdown; keep project choices below the main task field so tag creation cannot shift its alignment. Comma-separated entry remains a no-JavaScript fallback. Store normalized `project_tags` as at most ten distinct names, each up to sixty characters; compare names case-insensitively and preserve their first spelling. New subtasks inherit their parent's tags unless an explicit tag list is supplied; later changes affect only the edited task. Legacy tasks default to no tags. The Project filter combines with status tabs and keeps ancestor context for matching subtasks. Clear tab archives only tasks matching both filters. Tags survive completion, cancellation, clearing and restoration. Successful saves update chips and reusable tag choices; failed saves retain the previous confirmed tags and editor draft.
