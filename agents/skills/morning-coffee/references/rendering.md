# Rendering a Morning Coffee snapshot

Collect and normalize source facts once, then render through the bundled helper:

```sh
python3 scripts/render_brief.py /tmp/snapshot.json /tmp/morning-coffee.html
```

The helper uses only Python's standard library. It reads sibling `assets/brief.css` and `assets/brief.js`, then inlines both into the output. It does not call providers, update memory, or open a browser. The resulting report makes no network calls during rendering. Links remain ordinary user-initiated navigation. Keep raw collection data and previews temporary; publish new reports through [daily-history.md](daily-history.md). Never commit real report data with the helper.

The daily history helper consumes anonymous `availability` from [focus-and-exercise.md](focus-and-exercise.md), derives `day_plan`, and adds history/change metadata. The active [Morning Coffee workspace](workspace.md) keeps chosen work, source suggestions, calendar/local plan actions, local tasks and all core domains visible throughout the day. Source refreshes use the Coffee layout and preserve chosen order and drafts. Historical Tea snapshots retain their compact presentation for archive compatibility; they do not define a separate new workflow. Supporting evidence is expandable and the full change audit remains in the snapshot.

The root JSON object has `schema_version: 1` and these fields. Strings are plain source text, never HTML. Display times in 24-hour HH:MM, preferring authoritative timestamps; normalize legacy 12-hour UI time fields without rewriting source prose:

- `report`: `title`, `page_title`, `eyebrow`, local `date`, `time`, IANA `timezone`, optional `preview_label`, and optional legacy `footer` (not rendered).
- `coverage`: one compact string for the coverage banner, or an empty string when no notice is needed.
- `priorities`: array of `{title, context, action, done, evidence}` with stable `id` and optional verified `status` (`open`, `in_progress`, `blocked`, `completed`, `resolved`, `cancelled`). Completed/resolved/cancelled items are excluded from the default remaining-work list. `done` is the completion criterion, not a boolean. Evidence is `{paragraphs: [string], links: [{label, url}]}`.
- Legacy `okr` data is ignored; Quarter plan is no longer rendered.
- `agenda`: `{coverage, events}`. Every event has `{id, start, end, time, title, url, join_url, join_label}`; `start`/`end` are authoritative offset-aware timestamps (or exclusive-end all-day dates), needed by the interactive calendar. Display-only time strings are never scheduling evidence. Optional `all_day` identifies all-day events; optional `free` and `tentative` booleans add explicit labels. Retain all in-scope events.
- `oncall`: `{schedule, state, responder, shift_label, shift, dashboard_url, counts, note}`. Counts is `{active: integer, triage: integer}` from verified incident data. Omit unsupported counts rather than guessing.
- `rfcs`: `{window_label, database_url, coverage_label, coverage, items}`. An item has `{id, title, url, author, submitted_local, request_emoji, request_label, user_approved, approval_status, summary, relationship, next_action, approval_url}`. Only the collector decides inclusion in the exact In-Review / rolling-14-day window, and only verified user approval sets `user_approved: true`.
- `reviews`: `{collected_label, scopes: [{label, url}], items}`. Items are the complete, deduplicated eligible queue in canonical oldest-first order, after excluding personal approvals without an explicit re-request. Each has `{repository, number, url, title, queue, teams, author, readiness, reviewDecision, mergeStateStatus, ci, effort, updatedAt, summary, changedFiles, commitCount, additions, deletions}`. `authorOnTransport` is true/false for complete roster coverage and null when membership is unknown. `authorRoster` is `{status, note}` with status complete/partial/unavailable, and `personalReview` reports excludedCount, reRequestedCount and unknownCount. Default Authors is Transport team only for a complete roster; otherwise Everyone with a coverage note. `queue` is `direct` or `team`; direct takes precedence over overlaps. `author` is `{login}` or null; `readiness` is `{status, facts}`; `ci` is `{passing, failing, pending, total}` with optional `unknown`; an unavailable total is null; `effort` is `{size, label, inputs, driver}`. Size is S/M/L. Missing or invalid update timestamps render as unavailable. Do not retain full commits, files, raw bodies, or checks in this rendering snapshot. Derive and copy source fields programmatically; author only the concise recommendation/summary text instead of reproducing bulk JSON through the model.
- `yesterday`: `{date, coverage, items: [{title, content}]}` using the same evidence shape as priorities.
- Optional `submitted_plan`: latest same-date/timezone locally saved `{date, timezone, submitted_at, blocks: [{kind, start, minutes}]}` where `start` is local minutes after midnight. Publication and live workspace reads reload it from the configured root. The workspace supports editing and saved-block removal; historical archives preserve their original view. Keep actual calendar events distinct from submitted choices.
- Optional `review_state`: root-wide personal metadata keyed by `pr|<canonical_url>` or `rfc|<canonical_url>`. Each record is `{version: 1, kind: "pr"|"rfc", url, done: boolean, updated_at}` with an offset-aware save time. Load it through `review_state.load_review_state(root)` at publication and again when opening a local interaction session. Render **Done locally** separately from source approvals/readiness. PR **Review progress** defaults to **To review**; **All** and **Done locally** keep marked rows accessible. Keep all source rows and full eligibility/distribution totals. Local marks persist across days and source update noise; explicit undo or strict verified later request evidence may reopen work. Display personal timestamps in local 24-hour HH:MM.
- Optional `review_interaction`: ephemeral session `{endpoint, token}` enabling authenticated local review saves. It belongs only in temporary session HTML; publication strips it from archives. [Local interactions](plan-submission.md) describes unified workspace delivery and legacy archive compatibility. Failed saves preserve the last confirmed UI state.
- Optional `work_suggestions`: additional source-backed work with stable `id`/`source_id`, title/action, source URL, optional `project_tags` and a verified `material_key`. The workspace separately reconciles accepted/dismissed versions and chosen work. Material keys exclude collection times and generated prose; PR commits alone do not establish re-requested work.
- Optional `review_identity` and per-row `localReRequest`: verified current reviewer/target identities and strict later source-event evidence, defined in [personal review policy](personal-review-filter.md). Plain inferred re-request booleans are insufficient.
- Live-only `workspace`: sanitized durable selected priorities, suggestions, accepted mappings, version/date/timezone, current refresh status and non-secret bridge availability/error metadata. `workspace_interaction` supplies temporary status/refresh/start/suggestion endpoints and token. `plan_removal` supplies the temporary saved-block removal endpoint/token. These belong only to temporary sessions; publication strips all workspace and interaction capabilities from archives. The server loads chosen unfinished priorities and user answers over source recommendations before rendering.
- Optional `status_checks`: records `{section, id, title, outcome, question, attempts}`. Use `outcome: "uncertain"` only after independent validation leaves the item's status unknown; verified records may use `"verified"` and omit `question`. Each attempt is `{source, method, checked_at, result}` with an offset-aware time and the actual attempted authoritative lookup/result; optional `url` identifies its evidence. `section` and `id` match the stable source item or priority. Tea renders questions only for uncertain records with at least one valid recorded attempt, with attempted evidence in details. Plain unknowns without a check are collection work, not questions for the user. Never manufacture checks during format-only previews. Attribute user answers separately, preserving their time and the source-observed state.

The section navigator, readiness/effort distributions, and request totals derive from snapshot rows. They summarize the full retained queue, independent of the Authors default; while the table defaults to ten rows. Filters, adjustable 10/25/50/All pagination, and clear controls operate on the existing DOM; no additional fetching or re-ranking occurs. Every PR is included in the HTML, and all remain visible if JavaScript is unavailable.

# Dense presentation contract

Workspace order: source status/Refresh/Start today controls, count navigation, visible Today and on-call/incidents side by side, local tasks, chosen priorities and separate suggestions, unsaved interactive calendar, full RFC/review queues, previous-weekday outcomes; no report footer. Reviews use the full reading width with existing filters/pagination. Coffee has no closed wrapper around its main domains. Preserve the existing compact Tea layout only when reading a historical archive without workspace mode.

Use aligned ledgers for priorities, RFCs, and PRs, with readable typography, moderate row spacing, hairlines, and broad use of available width. The bundled theme is a cutesy Japanese café crossed with retro 8-bit games: ivory panels, cocoa pixel outlines and hard shadows, sakura Coffee accents, matcha Tea accents, CSS pixel cup sprites and decorative kaomoji. Monospace headings add character while body text stays readable. Essential metadata remains comfortably readable; do not shrink it to achieve density. Show data-grounded readiness and size distributions, count navigation, and review-size glyphs. Use muted semantic accents with readable labels and reserve a tinted interruption for coverage. Keep contrast and keyboard focus clear on the pastel reading surfaces. No decorative image assets are needed.

Keep each priority's action and completion checkpoint visible. Keep PR title, author, Direct/Team source, team tags, readiness, CI counts, and numeric size inputs visible. Coffee exposes PR authors and a short neutral summary, RFC proposal summaries/next actions, and Yesterday’s outcomes. Put only additional PR context in supporting `details`: a full summary when it replaces the shortened row summary, unique effort drivers, additional readiness evidence and timestamps. Omit an empty disclosure; author, summary, size inputs and status appear once per row. Priority/RFC evidence may also use disclosures. Never remove facts to achieve density.

Responsive grids reduce to one column on narrow screens. Wide ledgers span the full reading width; narrow layouts stack fields with no fixed minimum column widths. Explicit table roles preserve row/column semantics when CSS changes table display. Label size shorthand (`f` files, `c` commits), approval checkmarks, and request emojis. Distribution counts must also be readable as text and accessible labels.

Coffee begins with optional plan blocks unplaced unless restoring a successfully submitted plan. Dragging or placement opts a block in. The Coffee calendar view spans 08:30–17:00. A saved plan initially hides the editor; successful submission hides it immediately. Today’s Edit schedule restores editing. Full-day scheduling evidence and saved choices remain intact. Today combines actual events with distinctly labelled local blocks and saved-block Remove actions; update rows only after matching acknowledged saves, including an empty plan after final removal. A saved-plan calendar may remain visible with immutable provider events and narrow local removal controls. Preserve unrelated task drafts, filters and scroll when refreshing plan/source sections.

- `todos`: current local tasks loaded from the configured report root; keep open work prominent with status/project filters and discoverable completed/cancelled/archive views. `todo_interaction` is an ephemeral local save capability stripped from published history. Local tasks have no due dates; tags and unfinished work persist across days. See [to-dos](todos.md).

Use the maintained layout and typography assets: quiet content boundaries, consistent spacing, readable sans-serif headings/body text and restrained monospace metadata. Keep the café identity in the masthead and accents. Primary PR controls stay visible; secondary filters use More filters with an active count. Routine provenance belongs in Queue coverage & sources, while incomplete approval/author evidence stays visible.
