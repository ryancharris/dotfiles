# Personal approval eligibility and Transport authors

After hydrating and de-duplicating the scoped review queues, resolve the authenticated login once. For every successfully hydrated non-draft candidate, fetch all pages of `GET /repos/{owner}/{repo}/pulls/{number}/reviews?per_page=100`. Fetch current targets only when that history establishes an effective personal APPROVED state; other states do not use target or timeline evidence. Restrict personal review evidence to the authenticated login, comparing case-insensitively.

Order that user's submitted reviews by `submitted_at` and review ID. The latest APPROVED, CHANGES_REQUESTED, or DISMISSED state governs. COMMENTED and PENDING do not negate a prior approval. A latest CHANGES_REQUESTED or DISMISSED state retains the candidate; a latest APPROVED state triggers the explicit re-request check. Preserve the effective review ID, state, submitted timestamp, review link, and commit ID as evidence. New head commits do not reset an approval.

Only for candidates with a latest effective personal APPROVED state, fetch all pages of `GET /repos/{owner}/{repo}/pulls/{number}/requested_reviewers?per_page=100`, combining the users and teams arrays. If those targets are unavailable, retain the candidate as incomplete and skip the timeline. Otherwise fetch every page of `GET /repos/{owner}/{repo}/issues/{number}/timeline?per_page=100`. Retain review-request event IDs, timestamps, actor, requested user, and requested team. Keep the PR only when a `review_requested` event occurs strictly after the approval and targets either the authenticated user who is currently requested, or a relevant configured dbt-labs team that is currently requested on that PR. Accept team targets represented by `requested_team` or a team-shaped `requested_reviewer`. Identify teams by verified ID or slug, limited to the configured discovery teams. A current request without a later explicit event, a request predating the approval, a request removed from the current targets, an unrelated team, or new commits does not establish a re-request. When several qualifying events exist, preserve the latest event and whether it targets the user or a team.

Exclude already personally approved candidates when complete review/current-target/timeline evidence establishes no later explicit re-request. Missing review history or unorderable review timestamps retains the candidate; on the approved branch, missing target data or incomplete timeline coverage also retains it with a source-specific coverage warning. Preserve excluded candidates in local collection evidence; count them separately from the displayed eligible queue. Do not interpret other users' approvals or the aggregate PR reviewDecision as the authenticated user's approval.

Resolve the exact dbt-labs team named Transport from GitHub metadata every run; its current slug is verified from the live response, not inferred from display text. Fetch all pages of team membership with role=all. Set each candidate's authorOnTransport from its returned author.login and this verified roster, comparing case-insensitively. This is an author-membership filter, separate from the requested-team filter. Default the Reviews waiting author filter to Transport, and offer Everyone so every eligible result remains available. Apply this filter with the existing request type, requested team, readiness, effort, text, and pagination controls. Keep all eligible rows in HTML, with unfiltered totals distinct from the filtered count. If exact team/roster coverage is unavailable, show Everyone and disclose the limitation instead of inventing membership or presenting an empty default as complete.

A collection is complete when every scoped query, candidate hydration, personal review history, required approved-candidate timeline, and exact team roster is accounted for. Include approvalExcludedCount and reRequestedCount; preserve per-PR personalReview evidence and authorOnTransport. Source systems remain read only.

Use the bundled `scripts/personal_review_policy.py` decision helper with complete, paginated source arrays; pass unavailable evidence as None. Its `excluded` flag decides eligibility, and its `coverage` and `reason` fields supply coverage notes. Keep raw evidence in temporary collection files, outside the thin rendering snapshot.

## Collect with the bundled helper

Use `scripts/collect_personal_reviews.py` after scoped discovery, hydration and draft removal. Supply a JSON array of URLs or objects with `url`, the already-verified login, and each configured review team. The helper de-duplicates URLs, enforces the allowed-owner boundary, runs up to eight PRs concurrently, and delegates eligibility to `personal_review_policy.py`:

```sh
python3 "$skill_dir/scripts/collect_personal_reviews.py" "$candidates_json" \
  --login "$login" --team transport --team ops-platform \
  --output-dir "$run_dir/personal-review-evidence"
```

The example teams must match this run's discovered configuration. Use a new temporary output directory per collection. It retains raw paginated responses and errors, and writes `summary.json`; stdout contains only compact per-PR decisions and aggregate counts. Join decisions back to the hydrated queue by canonical URL, use `excluded` for eligibility, and propagate every incomplete decision. `apiInvocations` counts gh invocations, not HTTP pages; pagination remains complete. Do not fetch these endpoints again after the helper succeeds.
