# T3 Code — hands-on round 2 (2026-11-12)

**Installed version tested: 0.1.5** (`/Applications/T3 Code (Beta).app`, `t3 --version` = v0.1.5). The latest release is v0.1.9 (2026-11-11). I did **not** upgrade: the cask is `auto_updates` and brew's metadata already says 0.0.45, so a `brew upgrade` can't be cleanly rolled back. All results below apply to 0.1.5.

**Isolation.** I ran the installed server as `t3 serve --base-dir /private/tmp/t3q/home --host 127.0.0.1 --port 55344` with `T3CODE_HOME` set to the same path. The user's `~/.t3` was not touched. The GUI is the web client that the same server serves (`--mode web`, the same React bundle as the desktop app). I drove it from an isolated headless Chrome and took screenshots with CDP `Page.captureScreenshot`, because `screencapture` lacks permission here. I did not launch the Electron shell, to avoid its real userData, URL-scheme and shim registration.

Only items that earlier rounds left unproven were tested. Earlier results (E-term, H2, H3, H4, X-config) are unchanged and come from t3-evidence.md / t3-*-result.json.

## Notes and side effects
- Running Codex under T3 (full-access) added `[projects."/private/tmp/t3q/repo"] trust_level = "trusted"` to `~/.codex/config.toml` (symlink into ~/dotfiles) and wrote 3 Codex session rollouts. Listed in artifacts-t3code.txt for central cleanup.
- The Codex agent created branch `fix/greet-hi` in the disposable repo. That came from the user's global AGENTS.md, not from T3.
- Emails: the GUI obfuscates the signed-in email. Provider cache files in the isolated profile do contain the account email and workspace ID; they were not copied into evidence.
- Processes started (server :55344, Chrome :55360, http.server :55371) were all stopped. The Electron app was never launched.
