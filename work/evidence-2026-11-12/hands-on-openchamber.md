# Hands-on: OpenChamber v2.7.0 (2026-11-12)

- Installed: OpenChamber 2.7.0 (CFBundleShortVersionString), `OpenChamber-2.7.0-mac-arm64.zip` from GitHub Releases. It is notarized (Developer ID 5J7WJGPA2Q, spctl accepted) and installed at /Applications/OpenChamber.app. It bundles OpenCode v2.2.6 at Contents/Resources/opencode-cli/opencode.
- CLIs used: Claude Code 2.1.318, codex-cli 0.167.1.
- Isolation: launched with `open -n -a OpenChamber --env OPENCHAMBER_DATA_DIR=/private/tmp/ocb/data --env XDG_{CONFIG,DATA,STATE,CACHE}_HOME=/private/tmp/ocb/...`. This kept the bundled OpenCode away from the user's ~/.config/opencode (which is symlinked into dotfiles) and ~/.local/share/opencode. The isolated data dir works like a fresh profile.
- GUI method: `screencapture` failed ("could not create image from display": no Screen Recording permission in this context), and `orca computer` had no Accessibility permission. I relaunched the app with `--remote-debugging-port=9471` and drove the real Electron window through Chrome DevTools Protocol (clicks, insertText, Page.captureScreenshot). The helper is $ORIGINAL_SCRATCHPAD/oc-scripts/cdp.mjs. Every screenshot below is the real app window.
- Screenshots: $ORIGINAL_SCRATCHPAD/oc-shots/

## Isolation and side-effect notes
- `~/.config/openchamber/managed-opencode/` (empty) was created at first launch even though OPENCHAMBER_DATA_DIR was overridden. This is a minor isolation leak.
- User OpenCode config, dotfiles, ~/.zshrc and ~/.zprofile are unchanged (verified).
- ~/.claude.json mtime changed. This is normal Claude CLI behavior when the Claude Agent provider and the `claude` TUI launch. I answered the TUI trust prompt "No, exit".
- The app and the bundled `opencode serve` were quit at the end. No processes remain.
