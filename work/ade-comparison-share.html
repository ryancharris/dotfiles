01

The requirements

Entry: what makes it an ADE

  • Integrated terminal An integrated terminal inside the app.
  • Native chat A native chat interface for agents, not only a terminal.
  • Delegation A parent agent delegates to child agents and collects their results.
  • Provider keys Bring-your-own API keys, including OpenRouter-style gateways and the major labs. A key passed through a hosted agent CLI counts; the route is recorded. Qualification requires a successful authenticated request on the tested route; an invalid-key 401 establishes transport only.

Hard requirements

  • H1 TUI or GUI per session Choose at launch, per pane or session, between the agent's own TUI and the app's GUI chat. Converting an existing conversation is not required.
  • H2 No product login No separate account or sign-in for the app itself.
  • H3 Respects terminal setup Respects the configured shell, startup files, env/PATH, aliases, prompt and keybindings. The shell executable and login-mode startup are separate checks. Emulator appearance is out of scope.
  • H4 Enterprise accounts (personal) Works with existing Enterprise OpenAI and Anthropic accounts. Hard for my setup; extra credit for a fresh setup.
  • H5 Out of box (general) Good defaults: a working agent without editing settings or config files. Hard for a fresh setup only.
  • H6 Diff and review Integrated, syntax-highlighted diff or review of agent changes.
  • H7 No config changes without consent Does not modify other tools' configs (Claude Code, Codex, Cursor, OpenCode, shell rc) without consent. Agent-CLI trust prompts do not count against the app; a visible wizard step with a Skip button counts as consent.

Extra credit (tie-break only)

  • Config in files Settings live in files rather than UI-only state.
  • Open source Source available under an open-source licence.
  • Free tier covers core The core workflow is free, with no core feature behind a paywall or upsell.
  • Linux (general) A Linux desktop build. Extra credit for a fresh setup.
  • Integrated browser (general) A browser inside the app. Extra credit for a fresh setup.
How this brief evolved

Entry, hard and extra tiers were settled on 12 November 2026 and replace the earlier six-app brief. Two picks share one grid: my setup (heavy dotfiles, Enterprise accounts) and a fresh setup (minimal dotfiles). Diff/review was promoted to a hard requirement, and H7 (no config changes without consent) was added after testing showed apps writing into other tools' configs. A hosted agent CLI that carries the provider key counts for entry, with the route recorded. Mobile and inline comments are optional and earn no credit.

Notable behaviour

  • Pane sends identified product analytics (git email as the distinct ID) on first open, before the opt-out is reachable, and writes MCP servers, skills and an AGENTS.md block into every agent's global config by default.
  • Orca installs status hooks into Claude Code, Codex, Gemini, Cursor and Hermes configs, on by default with no prompt. `orca agent hooks off` removes them; the status still reported enabled after removal.
  • Ghostex and Pane install skills into ~/.claude/skills; on this machine that path resolves into the dotfiles repo.
  • Orca (Yolo mode), Pane (permission prompts off, --dangerously-skip-permissions) and T3 Code (Full access) default new agents to full access.
  • T3 Code and OpenChamber enable usage telemetry by default, with an opt-out.
08

Method

  • Paper screen of every candidate against the entry and hard tiers, from docs and source; shortlist of 8.
  • Hands-on test of all 8 on 12 November 2026, each in an isolated profile or data dir with the real HOME read-only where possible. Fixed prompts (for example 'Reply with exactly: PASEO_OK') with transcripts and screenshots.
  • Provider keys tested with a fake key; a 401 from OpenRouter itself proves the request reached the gateway. Paseo also ran a real request with a disposable key.
  • H7 audited by diffing other tools' config files (sha and mtime) against a 09:58 baseline.
  • Grades are scoped and never summed. Extras break ties only.
  • Continuation audit reconciled the manifest with retained tests: launch-time TUI/GUI choice counts without conversation conversion; terminal Enterprise routes count consistently.
  • Paseo H3 follow-up used a saved alternate login-shell profile and representative input probes through the actual app PTY. It does not establish desktop key-to-byte translation or change the default profile.
  • Both audiences receive three ranked recommendations. Qualified and provisional labels distinguish completed verification from incomplete hard-requirement evidence; app statuses and cell grades are unchanged by ranking.
  • Fresh runtime validation closed the missing Paseo child/result receipt and Sheprd/Agentastic shell-input gaps. Invalid-key 401s are retained only as transport proof; authenticated API-key requests for those two apps remain incomplete without a valid key.

Limits of the evidence
Grades cover the tested version of each app on one macOS host on 12 November 2026, in isolated profiles. T3 Code was tested on 0.1.5; 0.1.9 is current and may differ. OpenAI Enterprise rests on the existing ChatGPT login whose plan claim is ent26. Paseo, Sheprd, T3 Code, Pane and OpenChamber opened non-login shells in the recorded routes. Named aliases and exports do not by themselves prove every startup file or input binding. H3 notes identify the missing scope. H7 grades for Sheprd, T3 Code, Agentastic and OpenChamber rest on one run each; other paths (skill-install commands, upgrades) may differ. Linux builds and most free-tier claims come from docs.
